# 播客来源取证

把公开播客变成可复核的来源证据链。先取得完整逐字稿，再从罕见表达、概念组合和论证顺序反向定位候选来源；始终区分一手材料、公共事实、常见观点和具有辨识度的二手解释。

## 核心原则

- 只访问公开页面和页面公开暴露的音频，不绕过登录、付费、加密或平台限制。
- 妙记转写会把音视频上传到用户自己的飞书云空间。执行上传前说明这一数据边界；若用户没有明确授权上传，先取得确认。
- 使用用户自己的 `lark-cli` 配置和用户身份。不要索取、展示、保存或打包 `appSecret`、访问令牌、设备码和个人 API。
- 完整逐字稿只用于本地研究和证据定位。对外报告仅保留必要短引文、时间戳和来源链接。
- “洗稿”是来源取证判断，不等于法律上的抄袭或侵权认定。没有创作者的书目、笔记或浏览记录时，不声称已经证明其实际阅读路径。

## 工作流

### 1. 建立独立工作目录

为每一期节目新建目录，至少分成 `audio`、`transcript`、`sources` 和 `report`。不要覆盖既有个案；需要重跑时新建版本目录。

记录：节目 URL、标题、发布日期、总时长、核验日期，以及是否使用了完整音频和完整逐字稿。

### 2. 获取公开音频

小宇宙公开单集页优先运行：

```powershell
python scripts/fetch_public_episode.py `
  --url "https://www.xiaoyuzhoufm.com/episode/..." `
  --output-dir ./audio
```

脚本从公开页面元数据提取音频地址，写入 `episode.json` 并下载音频。其他平台只在公开页面明确提供音频 URL 时下载；否则请用户提供本地音频，不尝试绕过访问控制。

### 3. 用飞书妙记生成逐字稿

执行前完整阅读 [references/lark-transcription.md](references/lark-transcription.md)。该文件规定认证、身份延续、相对路径、上传和等待转写的准确命令。

转写完成后确认：

- 输出存在且不是只有标题或 AI 摘要。
- 逐字稿包含从开头到结尾的时间戳，末尾时间接近节目总时长。
- 分析基于 Transcript，不照搬妙记 AI 总结。
- 人名、书名和英文引文只校正明显识别错误；保留原始逐字稿副本。

### 4. 建立“来源指纹”清单

通读逐字稿，先抽取 8-15 个检索锚点：

- 主播直接读出的英文原句、专名、冷门术语或罕见比喻。
- 两个以上不常共同出现的概念组合。
- 特定人物组合、例证顺序或“三步/四步”论证链。
- 从常见事实突然跳到的解释性结论。
- 开头的方法论和结尾的收束意象。

不要把作品原句、剧情、历史事实、基本书目信息或领域常识当成二手来源指纹。

### 5. 在30分钟内定位候选来源

完整阅读 [references/source-hunt-playbook.md](references/source-hunt-playbook.md) 和 [references/evidence-standard.md](references/evidence-standard.md)。按其中的 0-5、5-10、10-20、20-27、27-30 分钟节奏执行。

优先搜索精确短语和罕见组合，并按以下顺序取证：

1. 官方课程、播客页面及官方字幕。
2. 大学、研究机构、作者或出版社公开页面。
3. 可核对页码的论文全文、图书预览或合法开放版本。
4. 可靠摘要和书评，仅用于发现线索，不单独支撑强结论。

搜索结果页摘要只能当导航。必须打开来源正文，在上下文中验证作者真正提出了该判断。

### 6. 建立逐段证据表

复制 [references/evidence-template.csv](references/evidence-template.csv) 为个案文件。每条证据至少填写：

- 播客起止时间和关键判断。
- 来源作者、标题、URL、页码或来源时间戳。
- 双方必要的短引文或准确转述。
- 匹配类型、置信度和排除理由。
- 是否属于一手材料、公共事实或领域常识。

按最小可辨认论证单元切段。一个区间既有复述又有二手解释时拆成多个区间，避免把整段都计入覆盖率。

### 7. 计算不重复覆盖时长

先估算“有效论证时长”：从节目总时长中剔除片头片尾、广告、连续原文朗读、纯剧情复述、公共事实和无分析内容。把估算规则写入报告。

运行：

```powershell
python scripts/calculate_coverage.py `
  --evidence ./evidence.csv `
  --effective-duration 30:10 `
  --total-duration 34:05 `
  --output ./coverage.json
```

脚本会合并重叠区间，同一节目区间即使匹配多个来源也只计算一次：

- 严格覆盖：只计 `fingerprint`。
- 扩展覆盖：计 `fingerprint` 和 `structural`。

覆盖率是“可由来源链覆盖的论证时长”，不是翻译字数比例。时间边界含判断时用区间表述，不伪造秒级精确度。

### 8. 写结论与报告

按 [references/report-template.md](references/report-template.md) 输出。先给结论，再给最强证据、排除项、覆盖率、候选来源分工和限制。

结论强度必须与证据对应：

- 只有共同主题：写“思想相近，证据不足”。
- 有连续框架但无独特措辞：写“存在结构性改写迹象”。
- 有多个高辨识度组合且未披露来源：可写“观点与结构性洗稿高度疑似”。
- 只有逐句或近逐句对应且来源关系清楚时，才描述为直接翻译或文字性改写。

不要写“确定抄袭”“法律侵权”或主观动机判断。

### 9. 交付前质检

- 检查所有强证据都能从公开 URL 复核，短引文没有断章取义。
- 检查一手材料、公共事实和基本书目信息已从覆盖率中排除。
- 检查相互重叠的来源区间只计一次。
- 检查严格覆盖率和扩展覆盖率均给出分母和含义。
- 检查报告明确披露转写误差、来源共享学术传统和无法证明实际阅读路径的限制。
- 运行 `powershell -ExecutionPolicy Bypass -File scripts/scan-secrets.ps1 -Path .`，出现任何命中都先处理再打包。

## 失败处理

- 页面没有公开音频 URL：停止自动下载，请用户提供其有权使用的本地文件。
- 飞书返回缺少权限：保持原 `--as user` 身份，按 CLI 错误提示完成最小权限授权；不要改用 bot 绕过。
- 妙记尚未生成：使用 `--wait-ready`，不要转而把 AI 摘要当逐字稿。
- 找到多个共享同一学术传统的来源：报告“来源网络”并说明不能唯一归因，不把同一时段重复计给多个来源。
- 30分钟未找到高辨识度来源：如实输出“初筛未发现”，列出已检索锚点和待深挖方向，不强行指认。
